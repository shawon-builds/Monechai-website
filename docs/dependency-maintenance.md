# Dependency and repository security maintenance

Local configuration is prepared; remote activation requires owner approval. Browser settings show dependency graph, Dependabot alerts/security updates and Secret Protection disabled; CodeQL needs setup. Repository is public. Connector can read only; authenticated browser can view security settings. No hosted workflow run or scanning acceptance exists. See [access inventory](audits/2026-10-14-monechai-external-access-inventory.md).

Repository owner must accept maintenance responsibility or name a maintainer before launch. Review native alerts promptly, triage weekly, and apply tested updates before release. `.github/dependabot.yml` prepares weekly npm, GitHub Actions and Docker updates with at most three version-update PRs per ecosystem; security-update behavior follows GitHub settings. No automatic merge. Publishing this configuration activates external PR automation and requires approval. It does not enable separately disabled dependency graph/alert settings.

Quality workflow keeps `contents: read`, normal pull-request events, no production secrets and checkout credential persistence disabled. Actions pin full commit SHAs resolved from official repositories; Node/PostgreSQL pin inspected official-image digests with version labels. Pins prevent tag drift but require reviewed security updates. Check replacements against official release/tag/image metadata; align Docker stages, `.nvmrc`, CI database and local verification. Preserve lockfile integrity and guarded postinstall mitigation.

Approve dependency graph/alerts/security updates, native secret scanning/push protection and private vulnerability reporting through GitHub settings. Prefer native CodeQL default setup for JavaScript/TypeScript after hosted source is reviewed and updated. No paid scanner or privileged custom workflow is required. Validate harmless documented scanner fixtures only in a separately authorized disposable repository/branch; never publish credential patterns to this public repository. Local work does not certify scanner detection. Require successful quality/scanning checks through a reviewed main-branch rule after those checks exist. Decide how sole-owner review works before requiring a second reviewer.

MON-008 remains BLOCKED_UPSTREAM. Full `npm audit` must run and retain failure; production-only audit is separate. Current braces3.0.3 mitigation is narrow, version/layout/checksum guarded and does not clear npm advisories. Never suppress advisories or mark full audit passed from mitigation. Updates must pass pinned-runtime lint/typegen/typecheck, strict zero-skip disposable-DB tests, encrypted DB/photo restore, production build/E2E and preflight. Review release artifact identity and provider acceptance separately. No auto-merge/deploy.
